なぜ道具を知る必要があるか

AI はコードを書いてくれますが、あなたが名前を知らない道具を、あなたの代わりに選んではくれません。頼み方の幅が、そのまま作れるものの幅になります。

  • 「投稿を保存したい」と思っても、データベースという選択肢を知らなければ、AI への頼み方が浮かびません。
  • 「URL で誰かに見せたい」と思っても、無料で公開できる場所があると知らなければ、手元で動かして終わりになります。
  • AI は聞かれたことには詳しく答えますが、聞かれなかった選択肢はほとんど出してきません。

このまとめは、使い方ではなく「こういう道具がある」という地図です。細かい使い方は AI に聞けば教えてくれます。名前と役割だけ頭に入れておいてください。

このまとめは、手元のフォルダで動かす AI を使う前提です。作ったファイルをそのまま、下の地図の道具に置いたりつないだりできます。

使う人が触れるのは「公開する場所」のページだけです。保存や AI が必要になったら下の段を足し、左の GitHub と右の計測はどの段階でも付けられます。以下、箱ごとに中身を説明します。

公開する場所（ホスティング）

作ったページを URL で人に見せるには、どこかに置く必要があります。迷ったら Netlify か Vercel。どちらも無料枠があり、GitHub とつなぐと push するだけで公開されます。

サービス得意なこと向いているもの気をつけること
Netlify フォルダをドラッグするだけで公開できる（Drop）。フォームの受け取り、転送設定が手軽 イベントのページ、アンケート、小さなツール 無料は月300クレジットまで。使い切ると翌月までサイトが止まる。チームの非公開リポジトリは使えない（料金）
Vercel Next.js との相性が最高。AI の返事を少しずつ流す処理、東京リージョン Next.js のアプリ、AI チャット系 無料（Hobby）は個人・非商用のみ（料金）
Cloudflare Pages / Workers 世界中で速い。無料枠が広い。小さな DB（D1）や保存場所（R2）もそろう アクセスが多いもの、安く動かしたいもの 設定の用語が少し難しい
GitHub Pages GitHub だけで完結。一番シンプル 自己紹介、資料、説明書 ページを配るだけ。裏でプログラムは動かせない

どれも「ページを配る」のは得意ですが、長く動き続ける処理や、つなぎっぱなしの通信（チャットなど）は苦手です。そういうものは Render や Fly.io など、普通のサーバーを借りるサービスを使います。

データを置く場所

「誰かが入力したものを残したい」「人ごとに結果を分けたい」と思ったら、データの置き場が必要です。まず「誰が入力するか」で選ぶと失敗しません。

置き場どんなものか向いているもの
Google スプレッドシート 入力画面・共同編集・権限・履歴が最初からある プログラムを書かない人が中身を更新するもの（イベントの出店一覧、お知らせ）
Supabase データベース（PostgreSQL）に、ログイン・ファイル置き場・リアルタイムが一式ついている ログインがあるアプリ全般。初心者が最初に覚えるならこれ
Firebase Google の一式セット。ログインと、書いた瞬間に他の人の画面に出る仕組みが得意 チャット、スマホアプリ
Netlify Database Netlify に組み込みのデータベース（PostgreSQL）。管理画面から作れて、鍵の設定も自動 Netlify で公開しているアプリに、表のデータを足したいとき
Neon データベース（PostgreSQL）だけ。使っていないときは寝ていて安い（そのぶん、久しぶりの最初のアクセスは少し遅い）。Vercel などからつなげる 表のデータを検索・集計するもの
Upstash（Redis） 「名前 → 値」を一瞬で読み書きする場所 回数のカウント、ランキング、連打の防止
Netlify Blobs / Vercel Blob ファイルや小さなデータを丸ごと置く場所 画像のアップロード、設定一式の控え

データベースを使うときは、「誰がどの行を読めるか」の設定（Supabase でいう RLS）を必ず AI に確かめてください。忘れると、全員のデータが誰でも読める状態で公開されます。

コードの置き場と自動公開

git と GitHub は名前が似ていますが、別のものです。

gitGitHub
何かファイル修正時に「いつ・どこを変えたか」を残していくツールgit の記録を預けておく場所（Web サービス）
どこで動く自分の PC の中インターネット上
たとえゲームのセーブ機能セーブデータを預けるクラウド
これでできること履歴、巻き戻し控え、共有、公開先との連携

git だけでも使えますが、GitHub に置くと公開先とつながります。

これだけは覚えろ

GitHub を使うときによく出てくる操作は、この7つです。使う順に並べています。

機能意味
branch本番を変えずに試せる、別の作業ルートを作る
commit変更を記録する（セーブする）
push記録を GitHub に送る
pull request「この branch を main に取り込んで」とお願いする（GitHub だけの機能）
mergebranch で試した変更を本番に取り込む
pullGitHub の最新を手元に持ってくる
cloneGitHub のリポジトリを丸ごと手元にコピーする

手元で作り始めたときの流れです。①〜⑦は使う順番で、青は git の機能、ピンクの pull request だけが GitHub の機能です。試してイマイチなら、merge せずに branch を捨てれば main は元のままです。branch を手元で作った場合は、③は要りません。clone は、別の PC や他の人のリポジトリから始めるときに使います。

誰かと一緒に作るとき

それぞれが自分の branch で作業し、pull request で相手に確認してもらってから main に入れます。作業を始める前に pull して相手の変更を手元に取り込んでおくと、変更がぶつかること（コンフリクト）が起きにくくなります。

GitHub にコードを置き、公開先とつなぐのが基本の形です。一度つなぐと、あとは AI が直して push するだけで公開まで進みます。

  1. 手元で直す（AI に頼む）
  2. git で記録する（commit）
  3. GitHub に送る（push）
  4. Netlify / Vercel が気づいて、数十秒で公開する

この形にすると手に入るもの：

  • 履歴：いつ何を変えたかが全部残る。「最新版 (13).html」のようなファイル名での管理から卒業できる
  • 巻き戻し：壊しても、前の公開にボタン1つで戻せる
  • 確認用 URL：本番と別の branch に push すると、本番を変えずに試せる URL が自動でできる
  • 控え：PC が壊れてもコードが残る

公開リポジトリは中身を誰でも見られます。学生なら GitHub Education に申請すると、Copilot などが無料で使えます。

見る・広げる

公開したら終わりではなく、「何人が使ったか」「遅くないか」「壊れていないか」「どう届けるか」を測れる道具があります。どれも無料で始められます。

道具わかること・できること
アクセス解析（Netlify / Vercel の管理画面、Google Analytics、Plausible など） 開かれた回数、人数、どこから来たか。「ボタンが押された回数」は自分で数える仕組みが必要
Lighthouse Google の無料の健康診断。速さ・使いやすさ・検索されやすさを100点満点で採点し、直し方も出す。Chrome の「検証」に入っている
エラー監視（Sentry など） 使う人の画面で起きたエラーを、時刻やブラウザつきで知らせてくれる。「自分の PC では動くのに」に気づける
Google Search Console 自分のサイトが Google に載っているか、どんな言葉で検索されたか。「登録して」と頼める
OGP（シェア用の設定） LINE や X に URL を貼ったときに、画像つきのカードで出るようになる。HTML に数行足すだけ
独自ドメイン 〇〇.netlify.app を「自分の名前.com」のような URL にできる。年に千〜数千円ほど。買った場所で設定を数行足すと、Netlify / Vercel につながる

「検索で上に出る」には、他のサイトからリンクされることが一番効きます。作ったばかりのページは、登録されてもすぐには上に出ません。最初は SNS や QR コードで直接届ける方が早いです。

組み合わせレシピ

やりたいことから逆引きした構成例です。上から順に難しくなります。小さく始めて、足りなくなったら下の形に広げます。

やりたいこと構成
イベントの案内ページ、地図、自己紹介HTML 1枚 → Netlify Drop（ドラッグするだけ）
中身を他の人に更新してもらうスプレッドシート → ページがそれを読んで表示 → Netlify
感想や申し込みを受け付けるGoogle フォーム（ページに埋め込める。回答は自動でスプレッドシートへ）。見た目をページに合わせたいなら、HTML フォーム → Netlify Forms
申し込んだ人に自動返信メールを送るGoogle フォーム → Google Apps Script → Gmail
ボタンが押された回数、ランキングページ → Netlify / Vercel の Functions → Upstash
ログインして自分のデータを持つアプリNext.js → Vercel ＋ Supabase（ログインと DB）
AI に答えさせるアプリページ → Functions（鍵はここに隠す）→ AI の API
重い処理、定期実行、常に動くボットRender / Fly.io などのサーバー、または GitHub Actions の定期実行

AI への頼み方

道具の名前を一つ入れるだけで、AI の答えは具体的になります。知らないときは、「選択肢を並べて」と頼むのが一番の近道です。

いまいちな頼み方広がる頼み方
アンケートのページを作ってアンケートのページを作って、Google フォームを埋め込みたい
ログインできるようにしてSupabase のログインを使って、自分の投稿だけ見られるようにして（RLS も設定して）
公開したいGitHub に入れて、Netlify で push したら自動で公開されるようにして
速くしてLighthouse で測って、一番効くところから直して

迷ったときの万能の一文：

やりたいことは○○。使えるサービスを無料枠、難しさ、向き不向きで並べて、初心者に一番向いている組み合わせを勧めて。

つまずきやすい点

一番多い事故は、鍵（API キーやパスワード）を公開してしまうことです。

  • 鍵はページに書かない：HTML やブラウザで動く JavaScript に書いた鍵は、誰でも読めます。鍵は .env や管理画面の「環境変数」に置き、Functions の中だけで使います。.env は GitHub に入れません。
  • AI の API には使いすぎ防止を設定する：鍵が漏れたり、処理が繰り返し止まらなくなったりすると、請求が一晩で膨らみます。API の管理画面で、月の上限金額と通知メールを最初に設定します。
  • 無料枠には条件がある：Vercel の無料は非商用のみ、Netlify の無料は月300クレジットまでで使い切ると翌月までサイトが止まる、など。人に使われる前に一度確かめます。
  • 「非公開」と「限定公開」は違う：URL を知っていれば誰でも見られるページは、公開と同じです。人に見せたくないものにはパスワードかログインが要ります。
  • 学内・業務のデータは外のサービスに置かない：個人情報や業務の資料は、置き場の決まりを先に確認します。岡山大学なら学内の GitLab「IRonical（おいとま）」があります。
  • 公開すると、すぐ地球の反対側からボットが来る：アクセス解析の海外分は、ほとんどが巡回ボットです。数字は少し割り引いて読みます。
